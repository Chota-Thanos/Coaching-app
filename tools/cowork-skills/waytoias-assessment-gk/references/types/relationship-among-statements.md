# Relationship-among-statements

Confirmed from the 2026 answer key (real example below) — Tier 3, see
`../format-evolution.md`. The hardest format documented in this skill so
far: it doesn't just ask whether facts are true, it asks the reader to
reason about how true statements relate to each other logically.

## Structure and components

- A set of **base statements** (usually 3) about one topic — these are
  presented as given/true, not something to individually verify (though
  writing them, you should still make sure they're all actually true —
  see Accuracy in SKILL.md).
- A second layer of **relationship claims** — each one asserts a logical
  relationship between two of the base statements: one *validates*
  (confirms/supports) another, one *extends* (broadens the scope of)
  another, one *contradicts* another, and so on.
- A prompt asking which relationship claims are correct.
- Options are combinations of the relationship-claim numbers.

## Depth

The highest in this skill's format set. Getting this right requires: (1)
understanding each base statement well enough to know what it actually
implies, and (2) correctly classifying the logical relationship between two
such statements — which is a reading-comprehension and reasoning skill
layered on top of subject knowledge, not a substitute for it. A student who
knows the facts but doesn't parse the relationship claims carefully (e.g.
mistaking "extends" for "restates," or "validates" for merely "is
consistent with") will get this wrong even with full topic knowledge.

## Scope — selecting the statements and relationships

Base statements should describe a topic with real internal structure — a
programme with phases, an institution with an evolving mandate, a process
with stages — so that genuine validate/extend/contradict relationships
exist between them, rather than three unrelated facts where any claimed
relationship is arbitrary. Write the relationship claims precisely: the
difference between "validates" and "is merely consistent with," or between
"extends" and "repeats," has to be real and defensible, not a coin flip
based on vague wording — vague relationship claims make this format feel
unfair rather than hard.

## Skeleton

```
Consider the following statements with reference to <topic>:
1. <statement>
2. <statement>
3. <statement>

Which of the following relationships among the above statements is/are
correct?
1. <relationship claim, e.g. "Statement II validates the claim in
   Statement I.">
2. <relationship claim>
3. <relationship claim>

Select the answer using the code given below:
(a) <combination>
(b) <combination>
(c) <combination>
(d) <combination>

Answer: (x)

Explanation:
Answer is (x).

Statement 1, 2, and 3 are each individually accurate: <brief confirmation,
since the base statements are meant to be taken as given but should still
be verifiable>.

Relationship claim 1 is <correct/incorrect> because <precise justification
of why this does or doesn't count as validating/extending/contradicting —
name the exact reasoning link>.
Relationship claim 2 ...
Relationship claim 3 ...

<Self-contained paragraph on the topic that also models the reasoning
connecting its parts — this is the one format where the overview should
explicitly walk through the logical structure, not just the facts.>
```

## Variety reminders

- Rotate which relationship type (validates / extends / contradicts / is
  independent of) is the correct one across questions — don't let
  "validates" always be right and "contradicts" always be wrong.
- Use this format sparingly relative to others — it's demanding to write
  well and demanding to answer well; reserve it for topics with genuine
  internal structure rather than forcing it onto thin content.
