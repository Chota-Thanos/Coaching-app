# Assertion-with-basis

Confirmed from the 2026 answer key (real example below) — Tier 3, see
`../format-evolution.md`. Distinct from `assertion-reason.md`
(Statement-I/Statement-II): that format judges whether two claims are each
true and whether one explains the other; this format takes one claim as
given and asks which of several candidate facts actually count as evidence
for it. It's evidentiary reasoning, not truth-checking.

## Structure and components

- A single, often fairly complex, **assertion** — a claim the question
  treats as the thing to be justified, not something to be judged true or
  false itself.
- Several numbered **candidate bases** — facts that may or may not actually
  support the assertion.
- A prompt asking which basis/bases the assertion actually rests on.
  Real papers word this at least two ways — vary it rather than always
  using one:
  - "Which of the following is/are the **basis** of the above assertion?"
  - "Which of the following statements **support/supports** the above
    assertion?"
- Options are combinations of the candidate-basis numbers.

## Depth

High — the reader has to understand *why* the assertion would be true (or
at least plausible) and then judge whether each candidate fact is genuinely
relevant evidence for that reasoning, versus a true-but-irrelevant fact
sitting nearby. This is closer to source-criticism/historiography reasoning
than fact-recall — good fit for History and Science topics where claims
are built from multiple lines of evidence (archaeological, textual,
genetic, etc.).

## Scope — selecting the assertion and candidate bases

Choose an assertion that's genuinely built on a specific, identifiable body
of evidence (a documented scholarly argument, not something you're
inventing) — this format only works honestly when there's real supporting
material to reason about.

The usual trap is to include one candidate that's a true, well-known fact
which doesn't actually bear on *this* assertion — that's what separates
"I recognise this fact" from "I understand what this fact actually proves."

**But don't make that trap mandatory.** Real papers also run items where
*every* candidate genuinely supports the assertion and the key is "1, 2 and
3" — e.g. an assertion that communal political alignments originated in the
Montague-Chelmsford Reforms, where separate electorates being retained and
extended, their role in blunting a rising nationalism, and deprived classes
mobilising around the advantages they conferred are all real strands of the
same argument. That version is harder in a different way: with no dud to
eliminate, the reader has to evaluate all three on their merits instead of
scanning for the odd one out. Alternate between the two shapes so students
can't assume there's always one to discard — the same elimination-resistance
logic that drives the "how many of the above" variant elsewhere.

When every candidate does support the assertion, the explanation carries
more weight than usual: spell out the distinct strand each one contributes,
so the item still teaches rather than just confirming three ticks.

## Skeleton

```
Consider the following assertion:
<assertion>

Which of the following is/are the basis of the above assertion?
1. <candidate basis>
2. <candidate basis>
3. <candidate basis>

Select the answer using the code given below:
(a) <combination>
(b) <combination>
(c) <combination>
(d) <combination>

Answer: (x)

Explanation:
Answer is (x).

The assertion rests on <reasoning connecting the correct basis/bases to the
assertion>.

Basis 1 <does/does not> support the assertion because <justification>.
Basis 2 ...
Basis 3 ...
[For any basis that's a true fact but not actually relevant, say so
explicitly — that distinction is the whole point of the question.]

<Self-contained paragraph on the underlying evidence/topic.>
```

## Variety reminders

- Don't always make the "true but irrelevant" trap the same numbered
  position across questions.
- Vary how many of the candidate bases actually count as support — one, two,
  or all three — rather than defaulting to the same split every time. An
  all-three key is legitimate and should appear sometimes; a batch where
  exactly one candidate is always a dud teaches students to hunt for the dud
  instead of reading the argument.
