# Statement-based questions ("which" / "how many" are correct)

This is the workhorse UPSC Prelims format, and the one with the most
built-up guidance — refined from real example analysis (economics: demand
determinants). Two closing-prompt variants share one structure:

- **"Which of the statements given above is/are correct?"** — options
  present specific combinations of statement numbers. The reader can
  sometimes shortcut this by recognising one statement is definitely wrong
  and eliminating any option containing it.
- **"How many of the above statements are correct?"** — options are counts
  ("Only one", "Only two", "Only three", "All four"). This hides *which*
  statements are meant, so it forces the reader to actually judge every
  single statement independently rather than pattern-matching a partial
  combination. Reach for this variant when you want to prevent elimination
  shortcuts.
- **Negation** — "Which of the statements given above are **NOT**
  correct?" (or "how many... are NOT correct"). Same stem/statement
  structure, but the prompt polarity flips, so the option combinations have
  to be built around the *false* statements rather than the true ones.
  Confirmed common in Geography, Science & Tech, and International Events.
  Flip the polarity deliberately across a batch — don't let every question
  default to the positive framing, since a reader who's learned "always
  pick the true ones" will misfire the moment a negation appears if they
  haven't seen it mixed in during practice.

All three variants are rising in the "elimination-resistant" direction
since 2025 — see `../format-evolution.md` (Tier 2) — precisely because they
each remove a different shortcut a student might otherwise rely on.

## Structure and components

- **Stem**: sets a shared context or condition that all statements are
  evaluated against (e.g. "Other things remaining unchanged, market demand
  for a good might increase if...").
- **2–4 numbered statements**, each independently true or false — not a
  single compound claim split arbitrarily into pieces.
- **Fixed closing prompt** matching the variant chosen above.
- **Options**: for the "which" variant, specific plausible combinations —
  never all four statements listed singly as separate options, and never
  just "the obvious leftovers by elimination." For the "how many" variant,
  the four count options.

## Depth

Statement-based questions can sit anywhere from pure factual recall (each
statement is an isolated fact you either know or don't) up to conceptual
application (a statement requires applying a rule correctly, or hinges on a
fine distinction between two related-but-different ideas). Favour the
higher end: include at least one statement that tests a genuine distinction
or rule application, not just a fact lookup. In the demand example, the
strongest statement was the one testing "movement along the demand curve"
(caused by the good's own price changing) versus "a shift in the demand
curve" (caused by income, substitute/complement prices, tastes) — a
conceptual trap, not a memorisable fact.

A good spread across one item: 1 statement of plain recall, 1–2 statements
that apply a rule, and (often) 1 statement that looks right but trades on a
common misconception.

## Scope — how to select and relate the facts

Pull all the statements from **one tight conceptual cluster** — the same
underlying rule, mechanism, or entity — probed from different angles, not
scattered unrelated trivia stapled together under one stem. In the demand
example, every statement was a different determinant-of-demand scenario;
none of them was a random unrelated economics fact. This is what makes the
item feel coherent and lets the closing concept-overview paragraph (see the
shared explanation rules in SKILL.md) actually mean something — it can
explain the *one* rule that ties every statement together.

When picking which facts to include, look for a set where getting one wrong
plausibly means misunderstanding the same rule that governs the others —
that's what makes the wrong-answer patterns diagnostic rather than random.

## Skeleton — "which" variant

```
Consider the following statements:
1. <statement>
2. <statement>
3. <statement>
4. <statement>
Which of the statements given above is/are correct?
(a) <combination>
(b) <combination>
(c) <combination>
(d) <combination>

Answer: (x)

Explanation:
Answer is (x).

Statement 1 is <correct/incorrect>. <justification that proves it>.
[If incorrect: also name the trap — the half-true or adjacent idea that
makes this tempting.]
Statement 2 is ...
Statement 3 is ...
Statement 4 is ...

<Self-contained paragraph explaining the underlying rule/concept, written
so it teaches on its own, not just as a recap of the statements above.>
```

## Skeleton — "how many" variant

Same stem/statement block, but the prompt and options change:

```
How many of the above statements are correct?
(a) Only one
(b) Only two
(c) Only three
(d) All four
```

Explanation follows the identical structure — go through every statement
individually regardless of the variant; "how many" doesn't excuse skipping
the per-statement reasoning, since that reasoning is what proves the count.

## Variety reminders specific to this type

- Rotate which statement number carries the trap — don't always put it
  last (or first).
- Don't default to "2 of 4 correct" every time; let the true count vary
  genuinely across a batch/session (see SKILL.md's variety section). Track
  this as the count of **true** statements even in negation questions —
  using one consistent measure is what makes the spread meaningful across a
  batch that mixes positive and negation framings.
- For the "which" variant, vary how the correct combination is built —
  sometimes adjacent statements (1,2), sometimes non-adjacent (1,3),
  sometimes a single statement, sometimes three.
