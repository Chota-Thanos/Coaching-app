# Cross-topic / common-thread

> **Status: draft** — reasoned out from the user's description rather than
> a verbatim confirmed example yet (unlike the other Tier 3 files). Flag for
> tightening once a real example comes in.

Structurally this looks like statement-based, but it inverts that format's
core selection rule on purpose — see the note in "Scope" below. Worth
reading `statement-based.md` first so the contrast is clear.

## Structure and components

- A stem naming one shared, often narrow attribute ("Which of the following
  report to the Prime Minister?", "Which of the following are appointed by
  the President?", "Which of the following have a fixed five-year term?").
- Several numbered items, **each drawn from a different topic or subject
  area** — different bodies, schemes, offices, or entities that don't
  otherwise relate to each other except through the one shared attribute
  the stem names.
- Options are combinations of item numbers (or "how many" style).

## Depth

Tests breadth of recall across the syllabus rather than depth on one topic
— the reader has to remember the *same type of fact* (a reporting line, an
appointing authority, a tenure length) independently for several unrelated
entities they may have studied in entirely different contexts or weeks
apart. This is a different kind of difficulty from statement-based's
"understand one concept deeply" — it's "hold many separate facts precisely
enough to compare them against one shared criterion."

## Scope — selecting the items (this is the opposite rule from statement-based)

`statement-based.md` says to pull statements from one tight conceptual
cluster. This format does the **opposite on purpose**: deliberately choose
items from different, unrelated topics/subjects, connected only by the one
attribute the stem is testing. If the items turn out to actually belong to
one cluster (e.g. all four are constitutional bodies), the cross-topic
difficulty disappears and it collapses into an ordinary statement-based
question — the format only does its job when the items look, at a glance,
like they have nothing to do with each other.

International Relations/Events is a strong source for this format
(international bodies sharing structural attributes — headquarters,
reporting lines, membership rules — across otherwise unrelated topics), but
it can be built from any subject where a specific factual attribute (term
length, appointing authority, reporting line, founding year, membership
rule) recurs across many otherwise-unrelated entities.

## Skeleton

```
Which of the following <shared attribute, e.g. "report to the Prime
Minister">?
1. <item from topic A>
2. <item from topic B>
3. <item from topic C>
4. <item from topic D>

Select the answer using the code given below:
(a) <combination>
(b) <combination>
(c) <combination>
(d) <combination>

Answer: (x)

Explanation:
Answer is (x).

Item 1 (<topic A>) <does/does not> have this attribute because
<justification>.
Item 2 (<topic B>) ...
Item 3 (<topic C>) ...
Item 4 (<topic D>) ...
[Name the topic each item comes from explicitly in the explanation — part
of what makes this teach well is showing the reader the breadth being
tested, not just the individual facts.]

<Closing paragraph on the shared attribute itself — what determines it,
and why it cuts across these particular topics — rather than a paragraph
about any single item's topic.>
```

## Variety reminders

- Don't reuse the same shared attribute (e.g. "reports to the PM") across
  many questions in one session — vary which kind of cross-cutting fact is
  being tested (appointing authority, tenure, headquarters, founding
  legislation...).
- Make sure at least one wrong item is a genuine near-miss (something that
  seems like it should share the attribute but doesn't) rather than all
  three wrong items being obviously unrelated to the attribute.
