# Identify-from-clues

Confirmed from the 2026 answer key (real example below) — Tier 3, see
`../format-evolution.md`.

## Structure and components

- A stem naming a category but not the specific entity ("Identify the river
  of the Indian sub-continent on the basis of the following information").
- Several numbered clues, each a true fact about the (unnamed) entity.
- Four **named candidates** as options — not combinations of clue numbers,
  actual answer choices.
- Exactly one candidate satisfies *every* clue; the wrong candidates should
  each satisfy some but not all of the clues, or plausibly fit at first
  glance.

## Depth

Synthesis and elimination, not single-fact recall. The reader has to hold
all the clues in mind at once and check each candidate against the full
set — a candidate that fits 3 of 4 clues is still wrong. This is what
makes it harder than statement-based despite superficially looking like a
list of facts: there's no partial credit for matching most of the clues.

## Scope — selecting the clues and candidates

Pick an entity with enough distinct, well-documented attributes to support
3–4 clues that narrow uniquely to it (geography and science topics tend to
have this — rivers, missions, species, treaties). Choose the three wrong
candidates so each one plausibly satisfies at least one clue — a set of
candidates where the wrong ones are obviously unrelated to any clue defeats
the format; the difficulty should come from needing every clue, not from
the candidates being far apart.

## Skeleton

```
Identify the <entity type> on the basis of the following information:
1. <clue>
2. <clue>
3. <clue>
4. <clue>

Select the answer from the following:
(a) <candidate>
(b) <candidate>
(c) <candidate>
(d) <candidate>

Answer: (x)

Explanation:
Answer is (x) — <candidate>.

Clue 1 <matches/does not match> because <justification>.
Clue 2 ...
Clue 3 ...
Clue 4 ...
[For each wrong candidate, name which clue rules it out — this is usually
more instructive than only justifying the right answer.]

<Self-contained paragraph on the entity/topic, useful independent of the
puzzle framing.>
```

## Variety reminders

- Rotate which clue is the one that actually disambiguates (sometimes it's
  the first clue, sometimes the last) — don't always save the deciding clue
  for last.
- Vary the entity type across a batch/session (don't do five rivers in a
  row) even within one subject.
