# Rationale-selection and mechanism-selection

Confirmed from the 2026 paper: Q33 (Environment, mangroves — rationale) and
Q34 (Economy, Vizhinjam Seaport — mechanism). Two closely related shapes;
both replace "is this fact true?" with "is this *explanation* sound?".

## Rationale-selection

The stem asks which candidate best explains or justifies something:

```
Which of the following best explain(s) the rationale for <X>?
```

## Mechanism-selection

The stem asks *by what means* something achieves an effect, and every item
opens with "By …":

```
In what way(s) does <X> represent <a change / an achievement>?
1. By <mechanism>
2. By <mechanism>
3. By <mechanism>
```

## Depth

High, and distinctive: the items are **long, fluent, plausible-sounding
explanations with errors embedded inside them** — not discrete facts with
truth values. A reader skimming for familiar keywords will find them in
every option, because each item name-checks the right topic. The error sits
in the causal claim, not in the vocabulary.

The 2026 mangrove item is the model: one candidate rationale said mangroves
"store freshwater, making them ideal sites for paddy cultivation in saline
belts", another that their "salt-sensitive roots filter seawater" to create
freshwater aquifers. Both read smoothly and both invert the actual ecology —
mangroves are salt-*tolerant*, and their value is coastal protection and
livelihood support, not desalination or rice-growing.

This is one of the best formats for separating genuine understanding from
memorised association, precisely because recognition doesn't help.

## Scope — selecting the candidates

Pick a topic where the *reason* something works is itself substantive
knowledge — an ecosystem service, an infrastructure advantage, a policy
instrument's transmission channel. Then build wrong candidates by taking the
real mechanism and breaking one link in it: reverse a direction of effect,
swap a property for its opposite, or attribute the benefit to a plausible
adjacent cause.

Write the wrong candidates at the **same length and fluency** as the right
one. If the correct item is the long detailed one and the wrong ones are
short, the format is defeated by shape alone — in the 2026 items the correct
answer was consistently the one that packed several real, connected effects
together, so vary that too rather than making length a reliable tell.

The rigid option template `(a) 1 only / (b) 1 and 2 / (c) 2 and 3 / (d) 3
only` was used for both 2026 items — see `../format-evolution.md`.

## Skeleton

```
Which of the following best explain(s) the rationale for <X>?
1. <plausible rationale, with or without an embedded error>
2. <plausible rationale>
3. <plausible rationale>
Select the answer using the code given below:
(a) 1 only
(b) 1 and 2
(c) 2 and 3
(d) 3 only

Answer: (x)

Explanation:
Answer is (x).

Rationale 1 is <sound/unsound>. <Identify precisely which link in the causal
chain fails — name the property or direction that has been misstated, not
just "this is wrong".>
Rationale 2 ...
Rationale 3 ...

<Self-contained paragraph explaining the actual mechanism, so a reader who
picked a wrong rationale understands why the real one works.>
```

## Variety reminders

- Vary how many candidates are sound — 2026 used single-correct for both,
  but a set where two hold is legitimate and prevents "find the one good
  one" becoming the strategy.
- Rotate the error type across items: reversed direction of causation, an
  inverted property, a real effect attributed to the wrong agent, or a true
  benefit that simply isn't the *rationale* being asked about.
- Keep every candidate topically on-point. An item that wanders off the
  subject is eliminable without understanding anything, which wastes the
  format.
